# 02 滑动窗口

状态：🟢 最熟（9 题，含最大/最小滑窗）

## 一句话

滑动窗口三模式：**定长**（窗口长度固定）、**最小**（满足条件时收缩求最短）、**最大**（不满足条件时收缩求最长）。

## 框架要点

- 定长：先装够 k 个，再右进左出，维护窗口统计
- 最小 / 最大：右指针扩张 + 左指针收缩，用 while 维护「不变量」
  - 最小：while 满足条件 → 更新答案 → 收缩
  - 最大：while 不满足条件 → 收缩 → 更新答案
- 窗口统计常用：int[] cnt（字符） / HashMap + need/window 计数

## 易错点

- 收缩条件写错 → 死循环；「先更新答案再收缩」的顺序别反
- 字符计数用 int[128] 比 HashMap 快

## 滑窗自查清单（每道滑窗题做完后对一遍）

以 3.无重复字符的最长子串 总结的「存在 / 收缩 / 记录 / 遍历」四件套：

1. **存在性**：`map.containsKey(x)`（或计数 `cnt[x] > 0`）——判断"窗口内是否已有 / 是否满足条件"
2. **左边界收缩**：`left = last.get(c) + 1`（或 `while` 收缩）——把不满足的部分踢出窗口，不是重置
3. **状态记录**：`last.put(c, right)`（或计数增减）——每步都更新，忘了就错
4. **遍历**：右指针 `right` 从 0 扫到 `s.length()-1`，`charAt(right)` 取当前字符

易错三连（3 号题踩过的坑）：

- 别漏「上次位置在窗口内」的判断（`last.get(c) >= left`）
- 别忘了每步更新状态（`put` / 计数）
- 答案初始值用安全值（空串 / 全不满足时也要对），别随手 `MIN_VALUE`

> 做 209（最小滑窗）前先对一遍：它对应「最小」模式——满足条件时才收缩。
